When a device goes offline

DSM tells its administrators when an adopted device has been offline for 10 minutes — the bell in DSM, and on your phone with DSM's email or push notifications — once per outage, and when a new device is waiting to be adopted. Firmware updates are done in UniFi (UniFi Devices → a device → Update).

Adopting a device

  1. By name, with no typing on the device. A new or reset device looks for unifi on your network and informs to http://unifi:8080/inform. Make unifi point at this Synology (192.168.1.20) in your router's or Pi-hole's local DNS, and new devices appear above by themselves.
  2. With set-inform. Sign in to the device over SSH — a new or reset device is ssh ubnt@its-address, password ubnt; one adopted before uses that controller's device password (UniFi → Settings → System → Advanced → Device SSH Authentication). Then type:
    set-inform …
    The device appears above within a minute: adopt it in UniFi. If it stays at Adopting, give the same set-inform once more.
  3. Moving from another controller. Easiest is to restore that controller's backup (a .unf file) in UniFi here first — the devices then know this one already, and only need the set-inform above.
  4. DHCP option 43 on routers that offer it hands devices the address too; see your router's manual.

UniFi runs in Container Manager, which keeps it off the network's broadcasts: a device on another subnet, or announcing on port 10001, isn't found by itself — which is why the first two ways are the ones that work.

The address devices use

UniFi has to tell devices an address they can reach: inside Container Manager it only knows its own internal one. The package sets UniFi's inform host override to this; change it if the Synology's address changes, or to a name your devices can resolve. UniFi stops for a minute while it changes. Devices that can't reach the old address any more need set-inform again.

Each is checked before it's used: a port something else on this Synology has is refused. Changing the inform port means every device adopted on the old one needs set-inform with the new address, and new devices no longer find UniFi by name (that only works on 8080). DSM's firewall list (Control Panel → Security → Firewall → Edit Rules → Select from a list of built-in applications) has an entry for each.

Not published: 1900/UDP (UniFi announcing itself on the local network — broadcasts don't reach Container Manager's network), 6789 (the old mobile speed test) and 5514/UDP (remote syslog from devices). The guest portal (8880 and 8843) is only needed for a hotspot or guest Wi-Fi with a portal page.

UniFi is a Java application with a MongoDB database. Both take memory from the Synology whether the network is big or small, so on a NAS with 2–4 GB it pays to keep them modest. A home or small office (up to 30 devices, a few hundred clients) runs well on the smallest settings.

If UniFi runs out

UniFi stops when its heap is full (Java's OutOfMemoryError in UniFi's server log on the Maintenance tab), and the package starts it again — if that keeps happening, give it more heap. If the NAS itself is short (DSM's Resource Monitor shows memory full and swap in use), give UniFi and MongoDB less, or add memory. MongoDB's cache is the database kept in memory; 256 MB is plenty unless the statistics are kept for a long time.

UniFi's own backups

FileSizeMade

UniFi makes these itself, inside its data folder — early every Monday, as the package set it up (UniFi → Settings → System → Backups changes how often and how many). The package copies new ones into the unifi shared folder, autobackups/, once a day, so Hyper Backup and File Station see them. A .unf file is what UniFi restores anywhere — on this controller (Settings → System → Backups → Restore), a fresh one, or a Cloud Key — so it's the one to keep when moving.
